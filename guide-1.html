Presenting: open the slides, then press p for presenter view. It shows your notes, the next slide, and a timer, and it stays in step with the slides. Share only the slides window. Use the arrow keys to move, and f for full screen.

7:00 to 7:30

Part 1: Check in

The goal is that everyone can run one sketch by 7:30.

  1. Welcome and consent, 5 minutes. Before recording, explain that sessions are recorded and shared in Google Classroom, and that cameras can stay off. Ask for consent.
  2. Who is here, 5 minutes. Ask for name, what they teach, and one thing they have made or want to make.
  3. Run a sketch, 15 minutes. Most people should already have joined Pickcode. Help the rest in a breakout, so setup does not hold up the room.
  4. The shape of the workshop, 5 minutes. Cover the four parts, optional Classroom posting, and the visible labs.
7:30 to 8:00

Part 2: Concept and live coding

The one idea: a sketch is a Java program with its loop hidden, and a variable outside draw() is state that lasts between frames.

  1. Which lines run again? 7 minutes. Run SetupDraw. The console prints setup ran, then draw ran: 1, 2, 3.
  2. Predict the ball, 6 minutes. Collect predictions in chat before running MovingBall. Ask: nothing calls draw(), so who does?
  3. Trace it, 5 minutes. Draw the y-axis by hand. Frame 5 draws at 8, not 10, because the circle is drawn before y changes.
  4. Integer division, 5 minutes. In FaceDrift, 1 / 2 * mouseX is always 0, so the eyes stay still. Change it to 1.0 / 2.
  5. Port it, 5 minutes. IntegerTrace.java prints 0, 50.0, 3, 3.5, with no window.
  6. Hand off, 2 minutes. draw() is a method we did not call. Now we write one and call it.

Name the case for Processing here: it helps people see Java behavior that is hard to see in a console.

8:00 to 8:30

Part 3: Guided practice

Joshua Hans leads one main activity, with about 20 minutes of real work time.

  • Project: a fall-themed pumpkin stamp. Pressing a key stamps a pumpkin at the mouse.
  • Java idea: drawing a pumpkin is a method with arguments.
  • Breakouts: write code, review code, or ask a facilitator to live-code it.
  • Second facilitator: visit breakouts and note the questions that come up.
8:30 to 9:00

Part 4: Guest and close

Art Simon has taught AP Java with Processing since its beta. Read his Processing Foundation interview ↗

  • Conversation, 20 minutes. How did he get from fixed-output assignments to interactive graphics? How does he keep creativity alive in an AP course? What still works for students today?
  • Questions, 5 minutes. Offer the chat as well as open mic.
  • Close, 5 minutes. Ask each person what they will try with their learners. Classroom posting is optional, and posted work gets shown at the Session 2 check-in.
In the moment

Common questions

If you hearTry
“draw() only runs once.”Add frameRate(1) and watch the console.
“The ball moves because of circle.”Point to y = y + 2. circle only draws where it is told.
“Why does it print 0.0?”y is a float. Ask what would print if it were an int.
“I removed background and it broke.”Nothing broke. Each frame stays on screen, which shows the whole path.
“My variable resets every frame.”It is inside draw(), so move it above setup().
“A warning mentions pixelDensity.”It is expected in the desktop editor and can be ignored.
“Is this on the exam?”Variables, tracing, methods, and integer division are Unit 1.
