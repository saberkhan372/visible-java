The one that reframes everything

The PDE was hiding a class from you

When you pressed Run in Processing, the editor quietly wrapped your sketch in a Java class, turned your global variables into instance variables, turned your functions into methods, and wrote a main for you. You have been writing classes all along without seeing the outside of one.

You can see this for yourself. A Processing sketch, written out as ordinary Java with nothing hidden, looks like this:

The sketch
float y = 0;

void setup() {
  size(400, 400);
}

void draw() {
  ellipse(200, y, 40, 40);
  y = y + 2;
}
What Processing built for you
import processing.core.PApplet;

public class Sketch extends PApplet {

  float y = 0;

  public void settings() {
    size(400, 400);
  }

  public void draw() {
    ellipse(200, y, 40, 40);
    y = y + 2;
  }

  public static void main(String[] args) {
    PApplet.runSketch(
      new String[]{"Sketch"},
      new Sketch());
  }
}

Worth doing once. Set this up for real and run it — Happy Coding's Processing in Java walks through it step by step. Seeing your own sketch as a class, with main at the bottom, does more to explain the first month of AP CS A than any lecture will.

Note the pieces you already recognise: public class, a field, methods, and a main that creates an object. That is Unit 3 of the course, and you have been living inside it for a year.

Do not skip this

Watch the arrows move

Aliasing is the one topic where reading an explanation genuinely does not work. You need to see the boxes and arrows change as each line runs.

Java Tutor steps through Java line by line — forwards and backwards — drawing every variable, every object, and every reference between them. Paste in Trap 12, press forward four times, and watch what happens to the first object when both variables end up pointing at the second.

Do this the first week. It will save you a letter grade.
