Make objects visible

Session 2’s ball knows its walls. Now it becomes a class, so one set of rules can drive many balls, each starting in a different state. You watch two objects share code but not state, watch one object answer to two names, and put a small set of them in an array. In plain Java, the class gains private fields and a getter.

Java ideas
Classes, fields (the variables each object owns), constructors, new, methods, references (a variable that points to an object rather than holding it) and null, this, and a small array of objects traversed with a loop.
AP link
AP CS A Unit 3, writing classes, and Unit 4, arrays and how to traverse them. Free-response Question 2 asks students to write a whole class. Outside AP: any course that introduces objects, an ecosystem or particle project in creative coding, or a game with many characters.

0:00 · 10 minutes · Predict and discuss

One class, two balls

This is Session 2’s ball with its state and wall rules moved into a Ball class. Before anyone presses Run, answer the two questions. Then open BallObjects from the download and run it.

Ball a;
Ball b;

void setup() {
  size(400, 400);
  a = new Ball(40, 40, 1.5, 2);
  b = new Ball(300, 100, -3, 1);
}

void draw() {
  background(255);
  a.move();
  b.move();
  a.show();
  b.show();
}

class Ball {
  float x;
  float y;
  float xSpeed;
  float ySpeed;

  Ball(float startX, float startY, float startXSpeed, float startYSpeed) {
    x = startX;
    y = startY;
    xSpeed = startXSpeed;
    ySpeed = startYSpeed;
  }

  void move() {
    x = x + xSpeed;
    y = y + ySpeed;
    if (x > width - 20 || x < 20) {
      xSpeed = -xSpeed;
    }
    if (y > height - 20 || y < 20) {
      ySpeed = -ySpeed;
    }
  }

  void show() {
    circle(x, y, 40);
  }
}

  1. What will you see when it runs?

    two balls, bouncing on their own One starts near the top-left corner and drifts down and to the right, like Session 2’s ball. The other starts upper right and heads left, faster sideways and slower down. When their paths cross, they pass right through each other, because nothing tells either ball that the other exists.

  2. The wall rules are written once. How many times do they run each frame?

    twice Once for a.move() and once for b.move(). Inside move(), x means “this ball’s x.” Same code, different state.

Facilitator notes

Before running, ask what a third ball would have cost in Session 2: two more variables and two more ifs, copied. Then ask what it costs now. Let people feel the difference before anyone says “class.”

0:10 · 15 minutes · Short demo

Two objects, one frame at a time

The facilitator runs ObjectTrace: two balls from the same class, moving sideways only, at one frame per second. It prints both x values and stops after five frames. Write your answers to questions 3–6 first. 

Ball a;
Ball b;

void setup() {
  size(400, 400);
  frameRate(1);
  a = new Ball(350, 120, 15, 0);
  b = new Ball(100, 280, -10, 0);
}

void draw() {
  background(255);
  a.move();
  b.move();
  a.show();
  b.show();
  println("frame " + frameCount + ": a.x = " + a.x + ", b.x = " + b.x);
  if (frameCount == 5) {
    noLoop();
  }
}

// class Ball: the same as in BallObjects

  1. What does the console print for frame 1?

    frame 1: a.x = 365.0, b.x = 90.0 Each object starts from the numbers its constructor was handed. This time move() runs before the print, so frame 1 already shows one step.

  2. What does it print for frame 3?

    frame 3: a.x = 395.0, b.x = 70.0 a overshoots the wall and turns around, the boundary case from Session 2. b doesn’t notice. Each object has its own xSpeed.

  3. In setup(), change b = new Ball(100, 280, -10, 0); to b = a;. What do you see, and what is the line for frame 1?

    frame 1: a.x = 380.0, b.x = 380.0 One ball, moving two steps a frame. b = a copies the reference, not the ball. There is one Ball with two names, so move() runs on it twice a frame, and the two names always print the same number. On frame 2 it reaches 395, turns, and comes back to 380 inside the same frame.

  4. Undo that. Now rename the constructor’s parameters to x, y, xSpeed, and ySpeed, so its first line reads x = x;. What happens?

    frame 1: a.x = 0.0, b.x = 0.0 Both balls sit in the top-left corner as one quarter circle and never move. Inside the constructor, x now means the parameter, so x = x copies the parameter onto itself. The fields keep their default, 0. The fix is this.x = x;, which names the field on purpose.

What Processing hides

How can Ball call circle() and read width? Those belong to the sketch. Here is where the class ends up when Processing builds it.

What you wrote
Ball a;
Ball b;

void setup() { // ... }
void draw() { // ... }

class Ball {
  // fields, constructor, move()

  void show() {
    circle(x, y, 40);
  }
}
What Processing runs
public class BallObjects extends PApplet {

  Ball a;
  Ball b;

  // setup(), draw(), settings(), main()

  class Ball {
    // fields, constructor, move()

    void show() {
      circle(x, y, 40); // the sketch's circle()
    }
  }
}
  • Ball is a class inside the sketch’s class. Every class in a sketch, in any tab, is placed inside it.
  • That is how it can draw. circle() and width belong to the sketch around each ball. A plain-Java Ball stands alone, so it can’t.
Facilitator notes

Question 5 is the most valuable minute of the session. References are usually taught with box-and-arrow diagrams. Here the aliasing (one object with two names) is something you can watch. Ask people to explain the double speed before anyone says “reference.” The object-state diagram in the handout draws the same moment.

Question 6 is the most common constructor bug in student code, and Processing doesn’t warn about it. It is the honest reason this exists.

If someone deletes a = new Ball(…) by accident, Processing stops on a.move() with a NullPointerException. Declaring Ball a; gives you a name. Only new makes a ball. Inner classes are not on the AP exam, and nobody needs the term.

0:25 · 25 minutes · Guided build

From two objects to a small world

Work in BallObjects. Before each run, say what you expect. The supported missions end at BallArrayCheckpoint. If you fall behind, open that and carry on from there.

Supported

Mission 1

A third ball

Declare Ball c;, make it in setup() with c = new Ball(200, 300, 1, -2.5);, and add c.move(); and c.show(); to draw().

Expect  A third ball starting low in the middle and drifting up. You added four lines, and none of them is a wall rule.

Mission 2

A small array

Replace a, b, and c with Ball[] balls = new Ball[4];. In setup(), make each one: balls[0] = new Ball(60, 60, 2, 1.5);, balls[1] = new Ball(300, 100, -3, 2);, balls[2] = new Ball(200, 300, 1, -2.5);, balls[3] = new Ball(100, 250, -1.5, -1);. In draw(): for (int i = 0; i < balls.length; i++) { balls[i].move(); balls[i].show(); }

Expect  Four balls, each from its own starting state. Leave out one of the four new lines and Processing stops with a NullPointerException: an array of objects starts out empty.

Mission 3

Different sizes

Add a field float diameter; and a fifth constructor parameter that sets it. Draw with circle(x, y, diameter);, and in move() use float r = diameter / 2; in place of each 20. Give the four balls diameters 40, 60, 30, and 80.

Expect  Four sizes, and each one turns exactly where its own edge meets the wall. This is BallArrayCheckpoint.

Independent extension

Extension 1

Who is touching?

Add boolean touches(Ball other) to Ball. It returns true when dist(x, y, other.x, other.y) is less than (diameter + other.diameter) / 2. In draw(), fill a ball orange if it touches any other ball.

Expect  Within the first second, two balls overlap and both turn orange, then white again as they separate. One answer is BallTouch.

Extension 2 · optional

A grid of balls

Make Ball[][] grid = new Ball[3][3]; and fill it with nested loops. Put each ball at the center of its cell, with col - 1 as its horizontal speed and row - 1 as its vertical speed.

Expect  Nine balls in a three-by-three grid, each moving in a different direction. The one in the middle never moves. Why? One answer is BallGrid.

Facilitator notes

In mission 2, making the array and making the objects are two separate steps, and students mix them up for weeks. new Ball[4] makes four empty slots, not four balls. Let someone hit the NullPointerException on screen.

Mission 3 is where “different initial states” becomes real. One constructor, four calls, four different objects. It is also the first time a field changes how a method behaves.

Extension 1 is the first method that takes another object as its parameter. other.x reads another ball’s field. In AP Java, with private fields, that still works inside the Ball class itself. Extension 2 is optional here: 2D arrays belong to AP Unit 4, so keep it for those who want it.

0:55 · 15 minutes · Java transfer

Same objects, no window

The test: the output must match the ObjectTrace console line for line. Run each file with any method from Running plain Java. 

public class BallWorld {

  public static void main(String[] args) {
    Ball a = new Ball(350, 120, 15, 0);
    Ball b = new Ball(100, 280, -10, 0);
    for (int frame = 1; frame <= 5; frame++) {
      a.move();
      b.move();
      System.out.println("frame " + frame + ": a.x = " + a.getX() + ", b.x = " + b.getX());
    }
  }
}

class Ball {
  private double x;
  private double y;
  private double xSpeed;
  private double ySpeed;

  public Ball(double startX, double startY, double startXSpeed, double startYSpeed) {
    x = startX;
    y = startY;
    xSpeed = startXSpeed;
    ySpeed = startYSpeed;
  }

  /** One frame of motion in a 400 by 400 window: move, then turn around at any wall. */
  public void move() {
    x = x + xSpeed;
    y = y + ySpeed;
    if (x > 380 || x < 20) {
      xSpeed = -xSpeed;
    }
    if (y > 380 || y < 20) {
      ySpeed = -ySpeed;
    }
  }

  public double getX() {
    return x;
  }

  public double getY() {
    return y;
  }
}
frame 1: a.x = 365.0, b.x = 90.0
frame 2: a.x = 380.0, b.x = 80.0
frame 3: a.x = 395.0, b.x = 70.0
frame 4: a.x = 380.0, b.x = 60.0
frame 5: a.x = 365.0, b.x = 50.0

Identical. The fields became private and double, so a.x became a.getX(), a getter (a method that only reports a field). show() is gone, and width - 20 became 380.

Trace an array before you run it

ArrayTrace.java moves four balls for two frames, then traverses the array once to count and to find the farthest right. Write all five lines first.

public class ArrayTrace {

  public static void main(String[] args) {
    Ball[] balls = new Ball[4];
    balls[0] = new Ball(370, 100, 10, 0);
    balls[1] = new Ball(200, 200, -50, 0);
    balls[2] = new Ball(30, 300, -10, 0);
    balls[3] = new Ball(190, 50, 10, 0);

    for (int frame = 1; frame <= 2; frame++) {
      for (int i = 0; i < balls.length; i++) {
        balls[i].move();
      }
    }

    int right = 0;
    int farthest = 0;
    for (int i = 0; i < balls.length; i++) {
      System.out.println("balls[" + i + "].x = " + balls[i].getX());
      if (balls[i].getX() > 200) {
        right++;
      }
      if (balls[i].getX() > balls[farthest].getX()) {
        farthest = i;
      }
    }
    System.out.println(right + " in the right half; farthest right is balls[" + farthest + "]");
  }
}

// class Ball: the same fields, constructor, move(), and getX() as BallWorld.java
balls[0].x = 390.0
balls[1].x = 100.0
balls[2].x = 10.0
balls[3].x = 210.0
2 in the right half; farthest right is balls[0]

Two boundary cases hide in here. balls[0] reaches exactly 380 on frame 1, which is not past the wall, so it goes on to 390. balls[2] reaches exactly 20, which is not less than 20, so it goes on to 10. farthest starts at 0 and changes only when a larger x turns up: that is the standard find-the-largest traversal.

Both programs define a class named Ball, so each has its own folder. Run either one as a single file, or compile its folder with javac *.java. In an IDE, make each folder its own project.

Facilitator notes

Have people paste their BallWorld output next to the sketch’s console. A mismatch is usually printing before moving, which is a good conversation about the order inside draw().

In the array trace, most people get balls[2] wrong by turning it at 20. Point back to Session 2’s boundary cases: the same < versus <= question, now inside an object.

1:10 · 15 minutes · Colleague exchange

When does a variable become an object?

In groups of three or four. One person shares their screen. Everyone answers:

Discussion prompt. When would you first say the word object to students: before they feel the copying, or after? What is the smallest class you would ask them to design on their own, and what would show you they understood it?

“After the copying, every time. I’d have them build two balls the long way first and count the lines, then show the class as the fix for a problem they already have. The smallest class I’d ask for is one with two fields, a constructor, and one method that changes a field, like a Firefly that blinks. The evidence would be the object-state diagram: if a student can draw what b = a does, they understand references, whether or not the sketch looks good.”

Facilitator notes

Mix AP and non-AP teachers in each group. Creative coding teachers often introduce objects earlier, through particles and agents, and that perspective helps everyone.

Ask each group to put one sentence in the chat. Those sentences start Session 5’s studio.

Studio

AP-style multiple choice

What is printed?

int[] speeds = {2, -3, 5};
int[] copy = speeds;
for (int i = 0; i < copy.length; i++) {
  copy[i] = -copy[i];
}
System.out.println(speeds[0] + " " + speeds[1] + " " + copy[2]);
  1. 2 -3 5
  2. 2 -3 -5
  3. -2 3 -5
  4. -2 3 5
  5. -2 -3 -5

C  -2 3 -5 An array is an object, so copy = speeds copies the reference, just as b = a did. There is one array with two names, and the loop negates every element of it. B is the answer for anyone who thinks copy is a separate array. A says the loop changed nothing at all. D forgets the loop reaches index 2. E negates every element but forgets that negating −3 gives 3.
