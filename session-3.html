Make objects visible

Session 2 ended with a question from the group: could each traffic light be its own object? We start there. One Light class draws all three lights, then each light keeps its own on/off flag behind private fields, with a getter and a setter, the way AP CS A writes classes. A walk button shows the sketch passing signals between objects. Then Joshua Hans’s confetti puts many objects on the screen at once. The ball from Session 2’s extra practice covers the same ideas, plus references and a first array, for anyone working on their own.

Java ideas
Classes, fields (the variables each object owns), constructors, new, methods, private fields with getters and setters, boolean flags, references (a variable that points to an object rather than holding it) and null, this, and a small array of objects traversed with a loop.

Part 2 · From Session 2’s traffic light

Could each light be an object?

In Session 2’s debrief, someone asked whether each light could be its own object. The three lights ran the same code with different numbers: a center, a bright color, and a dull color, plus a distance check for clicks. Three sketches answer the question one step at a time. Each section shows a short block, not the whole sketch: run the sketch and watch it while you read.

Step 1 · One class, three lights

The same picture as Session 2, drawn by a Light class, written once, and three Light objects. Open TrafficLightObjects from the download, and have Session 2’s TrafficLightCheckpoint open beside it.

Light red = new Light("red", 510, 55, 230, 40, 40, 90, 30, 30);
Light yellow = new Light("yellow", 510, 115, 250, 210, 40, 90, 80, 20);
Light green = new Light("green", 510, 175, 60, 200, 80, 25, 75, 35);

public void mousePressed() {
  if (red.contains(mouseX, mouseY)) {
    state = "red";
  } else if (yellow.contains(mouseX, mouseY)) {
    state = "yellow";
  } else if (green.contains(mouseX, mouseY)) {
    state = "green";
  }
}

class Light {
  String name;
  int x;
  int y;
  int onRed, onGreen, onBlue;
  int offRed, offGreen, offBlue;

  // The constructor copies its nine parameters into the fields.

  void display(String state) {
    stroke(0);
    if (state.equals(name)) {
      fill(onRed, onGreen, onBlue);
    } else {
      fill(offRed, offGreen, offBlue);
    }
    ellipse(x, y, 50, 50);
  }

  boolean contains(int mx, int my) {
    double distance = Math.sqrt(Math.pow(x - mx, 2) + Math.pow(y - my, 2));
    return distance <= 25;
  }
}

  1. This sketch draws the same picture as the Session 2 checkpoint. Which lines from Session 2 are gone, and where did they go?

    three copies became one The three if/else blocks in drawLight() became display(), and the three distance lines in mousePressed() became contains(). Each is written once. The numbers that made the copies different moved into the constructor calls.

  2. How many classes are there, and how many Light objects? When yellow.display(state) runs, which x and y does it use?

    one class, three objects Each object keeps its own fields, so inside yellow.display(state), x is 510 and y is 115. Same code, different state. The ball below works the same way.

  3. Who knows which light is on: each light, or the sketch?

    the sketch state lives in the sketch, and a light only compares it with its own name. Another design gives each Light a boolean on field and a method to switch it. Then a click has to turn one light on and the other two off. Neither design is wrong. Which would you teach first? Step 2 is the other design.

Step 2 · Each light keeps its own flag

Session 2’s timer version, rebuilt from objects. Each Light keeps a boolean that says whether it is on. The Car keeps its own position and speed. The fields are private: other code asks a light with a getter, isOn(), and tells it something with a setter, setOn(). Open TrafficLightFlags. It runs like TrafficLightTimer, frame for frame.

Light red = new Light(510, 55, 230, 40, 40);
Light yellow = new Light(510, 115, 250, 210, 40);
Light green = new Light(510, 175, 60, 200, 80);
Car car = new Car(40, 305);

// In draw(): ask the lights, then tell the car.
if (green.isOn()) {
  car.setSpeed(3);
} else if (yellow.isOn()) {
  car.setSpeed(1);
} else {
  car.setSpeed(0);
}
car.move();

// One light on, the other two off.
public void turnOn(Light light) {
  red.setOn(false);
  yellow.setOn(false);
  green.setOn(false);
  light.setOn(true);
}

class Light {
  private int x;
  private int y;
  private int r;
  private int g;
  private int b;
  private boolean on;

  // The constructor copies its five parameters. Every light starts off.

  public boolean isOn() {
    return on;
  }

  public void setOn(boolean on) {
    this.on = on;
  }

  // display() draws full color when on, a third of each part when off.
}

  1. Which methods are getters, and which are setters? Where does the sketch ask a light a question, and where does it tell the car something?

    ask, then tell isOn() is a getter: it returns the flag and changes nothing. We name this boolean getter isOn rather than getOn, which is a naming convention, not a Java rule. setOn() and setSpeed() are setters: each changes one field and returns nothing. The if/else asks the lights, and each branch tells the car. The lights never talk to the car: the sketch coordinates them, and never touches a field itself.

  2. The fields are private. In setup(), replace green.setOn(true); with green.on = true;. Will it compile?

    yes, in a sketch Processing puts every class in a sketch inside the sketch, and Java lets an outer class reach the private fields of a class nested inside it. Pickcode works the same way when the class is written in Sketch.java. Move Light into its own .java file and the same line stops with on has private access in Light. In a sketch, private is a promise you keep yourself. In a separate class, the compiler keeps it for you.

  3. The sketch calls turnOn(yellow). Inside turnOn, which object is light?

    the same yellow light Passing an object passes a reference to it, not a copy. light and yellow are two names for one Light, so light.setOn(true) turns on the light the sketch draws. The ball below shows the same idea with b = a.

Step 3 · A walk button

In Session 2, the group suggested a pedestrian button that makes the car stop no matter what. Open TrafficLightWalk and click the button on the pole. Two more classes join the sketch: a WalkSign, which knows whether someone pushed the button and whether it says WALK, and a Pedestrian, who knows whether they are crossing. The car now stops at a stop line, not wherever it happens to be. The objects never talk to each other directly. Each frame, draw() asks one object about its flags with a getter, and tells another what to do with a setter:

// A push on green ends the green now.
if (walkSign.isRequested() && green.isOn()) {
  changeLight();
  counter = 0;
}

// Red, a push, and no car in the way: WALK.
boolean carIsClear = car.getFront() <= STOP_LINE || car.getBack() >= CROSS_RIGHT;
if (red.isOn() && walkSign.isRequested() && carIsClear) {
  walkSign.setRequested(false);
  walkSign.setWalk(true);
  person.startCrossing();
}

// The person walks. On the other side, the sign goes back to WAIT.
person.walk();
if (walkSign.isWalk() && !person.isCrossing()) {
  walkSign.setWalk(false);
}

  1. The light is green, and the car’s front bumper is just past the stop line. You push the button. What happens, in order?

    yellow, red and WALK together, then green Green ends at once. The car is past the line, so it keeps going, slowly on yellow. Three seconds later the light turns red. By then the whole car is past the crosswalk, so the sign says WALK on that same frame, and the person takes about two seconds to cross. The sign goes back to WAIT, red finishes its three seconds, and then the light turns green.

Facilitator notes

This is all of Part 2. Project the short block and the running sketch, not the whole file. People who worked on the traffic light have just felt the copying, which makes it a good moment to say the word class. Then hand off to Joshua Hans’s confetti.

Joshua Hans suggests private fields with getters and setters at step 2, the AP CS A norm. Question 5 is the catch: inside a sketch, private is not enforced. Worth saying before someone finds it by accident.

Nine constructor parameters in step 1 is a lot, and someone may say so. Step 2 answers with five: an off light is a third of each part of its on color, so off lights are a little darker than in Session 2.

Step 3 is optional. Run it rather than reading it all. The comment at the top of the sketch lists which flags draw() checks and what it changes. Say plainly that the sketch coordinates the objects: no object sends another a message.

In Pickcode, the classes can go inside Sketch.java, as they do here, or each in its own file. A separate file needs the sketch passed in to draw, which is more than this opener needs. All three sketches compile as plain Java, so they paste into Sketch.java.

The ball · Predict

One class, two balls

This is Session 2’s ball with its state and wall rules moved into a Ball class. Before anyone presses Run, answer the two questions. Then open BallObjects from the download and run it.

Ball a;
Ball b;

void setup() {
  size(400, 400);
  a = new Ball(40, 40, 1.5, 2);
  b = new Ball(300, 100, -3, 1);
}

void draw() {
  background(255);
  a.move();
  b.move();
  a.show();
  b.show();
}

class Ball {
  float x;
  float y;
  float xSpeed;
  float ySpeed;

  Ball(float startX, float startY, float startXSpeed, float startYSpeed) {
    x = startX;
    y = startY;
    xSpeed = startXSpeed;
    ySpeed = startYSpeed;
  }

  void move() {
    x = x + xSpeed;
    y = y + ySpeed;
    if (x > width - 20 || x < 20) {
      xSpeed = -xSpeed;
    }
    if (y > height - 20 || y < 20) {
      ySpeed = -ySpeed;
    }
  }

  void show() {
    circle(x, y, 40);
  }
}

  1. What will you see when it runs?

    two balls, bouncing on their own One starts near the top-left corner and drifts down and to the right, like Session 2’s ball. The other starts upper right and heads left, faster sideways and slower down. When their paths cross, they pass right through each other, because nothing tells either ball that the other exists.

  2. The wall rules are written once. How many times do they run each frame?

    twice Once for a.move() and once for b.move(). Inside move(), x means “this ball’s x.” Same code, different state.

The ball · Two objects, frame by frame

Two objects, one frame at a time

The facilitator runs ObjectTrace: two balls from the same class, moving sideways only, at one frame per second. It prints both x values and stops after five frames. Write your answers to questions 3–6 first. 

Ball a;
Ball b;

void setup() {
  size(400, 400);
  frameRate(1);
  a = new Ball(350, 120, 15, 0);
  b = new Ball(100, 280, -10, 0);
}

void draw() {
  background(255);
  a.move();
  b.move();
  a.show();
  b.show();
  println("frame " + frameCount + ": a.x = " + a.x + ", b.x = " + b.x);
  if (frameCount == 5) {
    noLoop();
  }
}

// class Ball: the same as in BallObjects

  1. What does the console print for frame 1?

    frame 1: a.x = 365.0, b.x = 90.0 Each object starts from the numbers its constructor was handed. This time move() runs before the print, so frame 1 already shows one step.

  2. What does it print for frame 3?

    frame 3: a.x = 395.0, b.x = 70.0 a overshoots the wall and turns around, the boundary case from Session 2. b doesn’t notice. Each object has its own xSpeed.

  3. In setup(), change b = new Ball(100, 280, -10, 0); to b = a;. What do you see, and what is the line for frame 1?

    frame 1: a.x = 380.0, b.x = 380.0 One ball, moving two steps a frame. b = a copies the reference, not the ball. There is one Ball with two names, so move() runs on it twice a frame, and the two names always print the same number. On frame 2 it reaches 395, turns, and comes back to 380 inside the same frame.

  4. Undo that. Now rename the constructor’s parameters to x, y, xSpeed, and ySpeed, so its first line reads x = x;. What happens?

    frame 1: a.x = 0.0, b.x = 0.0 Both balls sit in the top-left corner as one quarter circle and never move. Inside the constructor, x now means the parameter, so x = x copies the parameter onto itself. The fields keep their default, 0. The fix is this.x = x;, which names the field on purpose.

What Processing hides

How can Ball call circle() and read width? Those belong to the sketch. Here is where the class ends up when Processing builds it.

What you wrote
Ball a;
Ball b;

void setup() { // ... }
void draw() { // ... }

class Ball {
  // fields, constructor, move()

  void show() {
    circle(x, y, 40);
  }
}
What Processing runs
public class BallObjects extends PApplet {

  Ball a;
  Ball b;

  // setup(), draw(), settings(), main()

  class Ball {
    // fields, constructor, move()

    void show() {
      circle(x, y, 40); // the sketch's circle()
    }
  }
}
  • Ball is a class inside the sketch’s class. Every class in a sketch, in any tab, is placed inside it.
  • That is how it can draw. circle() and width belong to the sketch around each ball. A plain-Java Ball stands alone, so it can’t.
Facilitator notes

Question 5 is the most valuable minute of the session. References are usually taught with box-and-arrow diagrams. Here the aliasing (one object with two names) is something you can watch. Ask people to explain the double speed before anyone says “reference.” The object-state diagram in the handout draws the same moment.

Question 6 is the most common constructor bug in student code, and Processing doesn’t warn about it. It is the honest reason this exists.

If someone deletes a = new Ball(…) by accident, Processing stops on a.move() with a NullPointerException. Declaring Ball a; gives you a name. Only new makes a ball. Inner classes are not on the AP exam, and nobody needs the term.

Same objects, no window

public class BallWorld {

  public static void main(String[] args) {
    Ball a = new Ball(350, 120, 15, 0);
    Ball b = new Ball(100, 280, -10, 0);
    for (int frame = 1; frame <= 5; frame++) {
      a.move();
      b.move();
      System.out.println("frame " + frame + ": a.x = " + a.getX() + ", b.x = " + b.getX());
    }
  }
}

class Ball {
  private double x;
  private double y;
  private double xSpeed;
  private double ySpeed;

  public Ball(double startX, double startY, double startXSpeed, double startYSpeed) {
    x = startX;
    y = startY;
    xSpeed = startXSpeed;
    ySpeed = startYSpeed;
  }

  /** One frame of motion in a 400 by 400 window: move, then turn around at any wall. */
  public void move() {
    x = x + xSpeed;
    y = y + ySpeed;
    if (x > 380 || x < 20) {
      xSpeed = -xSpeed;
    }
    if (y > 380 || y < 20) {
      ySpeed = -ySpeed;
    }
  }

  public double getX() {

  }

  public double getY() {

frame 1: a.x = 365.0, b.x = 90.0
frame 2: a.x = 380.0, b.x = 80.0
frame 3: a.x = 395.0, b.x = 70.0

Identical. The fields became private and double, so a.x became a.getX(), a getter (a method that only reports a field). show() is gone, and width - 20 became 380.

Trace an array before you run it

ArrayTrace.java moves four balls for two frames, then traverses the array once to count and to find the farthest right. Write all five lines first.

public class ArrayTrace {

  public static void main(String[] args) {
    Ball[] balls = new Ball[4];
    balls[0] = new Ball(370, 100, 10, 0);
    balls[1] = new Ball(200, 200, -50, 0);
    balls[2] = new Ball(30, 300, -10, 0);
    balls[3] = new Ball(190, 50, 10, 0);

    for (int frame = 1; frame <= 2; frame++) {
      for (int i = 0; i < balls.length; i++) {
        balls[i].move();
      }
    }

    int right = 0;
    int farthest = 0;
    for (int i = 0; i < balls.length; i++) {
      System.out.println("balls[" + i + "].x = " + balls[i].getX());
      if (balls[i].getX() > 200) {
        right++;
      }
      if (balls[i].getX() > balls[farthest].getX()) {
        farthest = i;
      }
    }
    System.out.println(right + " in the right half; farthest right is balls[" + farthest + "]");
  }
}

// class Ball: the same fields, constructor, move(), and getX() as BallWorld.java
balls[0].x = 390.0
balls[1].x = 100.0
balls[2].x = 10.0
balls[3].x = 210.0
2 in the right half; farthest right is balls[0]

Two boundary cases hide in here. balls[0] reaches exactly 380 on frame 1, which is not past the wall, so it goes on to 390. balls[2] reaches exactly 20, which is not less than 20, so it goes on to 10. farthest starts at 0 and changes only when a larger x turns up: that is the standard find-the-largest traversal.

Both programs define a class named Ball, so each has its own folder. Run either one as a single file, or compile its folder with javac *.java. In an IDE, make each folder its own project.

Facilitator notes

Have people paste their BallWorld output next to the sketch’s console. A mismatch is usually printing before moving, which is a good conversation about the order inside draw().

In the array trace, most people get balls[2] wrong by turning it at 20. Point back to Session 2’s boundary cases: the same < versus <= question, now inside an object.

Two ways to use this move

Supported

Mission 1

A third ball

Declare Ball c;, make it in setup() with c = new Ball(200, 300, 1, -2.5);, and add c.move(); and c.show(); to draw().

Expect  A third ball starting low in the middle and drifting up. You added four lines, and none of them is a wall rule.

Mission 2

A small array

Replace a, b, and c with Ball[] balls = new Ball[4];. In setup(), make each one: balls[0] = new Ball(60, 60, 2, 1.5);, balls[1] = new Ball(300, 100, -3, 2);, balls[2] = new Ball(200, 300, 1, -2.5);, balls[3] = new Ball(100, 250, -1.5, -1);. In draw(): for (int i = 0; i < balls.length; i++) { balls[i].move(); balls[i].show(); }

Expect  Four balls, each from its own starting state. Leave out one of the four new lines and Processing stops with a NullPointerException: an array of objects starts out empty.

Mission 3

Different sizes

Add a field float diameter; and a fifth constructor parameter that sets it. Draw with circle(x, y, diameter);, and in move() use float r = diameter / 2; in place of each 20. Give the four balls diameters 40, 60, 30, and 80.

Expect  Four sizes, and each one turns exactly where its own edge meets the wall. This is BallArrayCheckpoint.

Independent extension

Extension 1

Who is touching?

Add boolean touches(Ball other) to Ball. It returns true when dist(x, y, other.x, other.y) is less than (diameter + other.diameter) / 2. In draw(), fill a ball orange if it touches any other ball.

Expect  Within the first second, two balls overlap and both turn orange, then white again as they separate. One answer is BallTouch.

Extension 2 · optional

A grid of balls

Make Ball[][] grid = new Ball[3][3]; and fill it with nested loops. Put each ball at the center of its cell, with col - 1 as its horizontal speed and row - 1 as its vertical speed.

Expect  Nine balls in a three-by-three grid, each moving in a different direction. The one in the middle never moves. Why? One answer is BallGrid.

Facilitator notes

In mission 2, making the array and making the objects are two separate steps, and students mix them up for weeks. new Ball[4] makes four empty slots, not four balls. Let someone hit the NullPointerException on screen.

Mission 3 is where “different initial states” becomes real. One constructor, four calls, four different objects. It is also the first time a field changes how a method behaves.

Extension 1 is the first method that takes another object as its parameter. other.x reads another ball’s field. In AP Java, with private fields, that still works inside the Ball class itself. Extension 2 is optional here: 2D arrays belong to AP Unit 4, so keep it for those who want it.

The grid as a method

Question 4 asks for one method over a 2D array. This file rebuilds the speeds from BallGrid and counts with nested loops, with no window. Predict the count and each row, then run it.

// Session 3, optional bridge: the BallGrid sketch as a 2D array method.
// AP free-response Question 4 asks for one method over a 2D array. No window here.
// Predict the count and the row-by-row output before you run it.

public class GridScan {

  /** Returns the number of balls in grid that are moving. */
  public static int countMoving(Ball[][] grid) {
    int count = 0;
    for (int row = 0; row < grid.length; row++) {
      for (int col = 0; col < grid[0].length; col++) {
        if (grid[row][col].isMoving()) {
          count++;
        }
      }
    }
    return count;
  }

  /** Returns the number of moving balls in the given row. */
  public static int countMovingInRow(Ball[][] grid, int row) {
    int count = 0;
    for (Ball b : grid[row]) {
      if (b.isMoving()) {
        count++;
      }
    }
    return count;
  }

  public static void main(String[] args) {
    Ball[][] grid = new Ball[3][3];
    for (int row = 0; row < grid.length; row++) {
      for (int col = 0; col < grid[0].length; col++) {
        grid[row][col] = new Ball(col - 1, row - 1);
      }
    }

    System.out.println(countMoving(grid));
    for (int row = 0; row < grid.length; row++) {
      System.out.println("row " + row + ": " + countMovingInRow(grid, row));
    }
  }
}

class Ball {
  private double xSpeed;
  private double ySpeed;

  public Ball(double xSpeed, double ySpeed) {
    this.xSpeed = xSpeed;
    this.ySpeed = ySpeed;
  }

  public boolean isMoving() {
    return xSpeed != 0 || ySpeed != 0;
  }
}
