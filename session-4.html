Make learning transferable

0:00 · 10 minutes · Predict and discuss

A prepared collection

Four balls, prepared for you in an ArrayList. Each one counts its bounces and stops for good on its third, turning gray. Before anyone presses Run, answer the two questions. Then open ActiveBalls from the download and run it.

ArrayList<Ball> balls = new ArrayList<Ball>();

void setup() {
  size(400, 400);
  balls.add(new Ball(60, 200, 4, 0));
  balls.add(new Ball(200, 60, 0, -3));
  balls.add(new Ball(300, 300, -5, 5));
  balls.add(new Ball(120, 330, 2, 6));
}

void draw() {
  background(255);
  for (Ball b : balls) {
    b.move();
    b.show();
  }
}

class Ball {
  float x;
  float y;
  float xSpeed;
  float ySpeed;
  int bounces;

  Ball(float startX, float startY, float startXSpeed, float startYSpeed) {
    x = startX;
    y = startY;
    xSpeed = startXSpeed;
    ySpeed = startYSpeed;
    bounces = 0;
  }

  void move() {
    if (bounces < 3) {
      x = x + xSpeed;
      y = y + ySpeed;
      if (x > width - 20 || x < 20) {
        xSpeed = -xSpeed;
        bounces = bounces + 1;
      }
      if (y > height - 20 || y < 20) {
        ySpeed = -ySpeed;
        bounces = bounces + 1;
      }
    }
  }

  void show() {
    if (bounces < 3) {
      fill(255);
    } else {
      fill(180);
    }
    circle(x, y, 40);
  }
}

  1. What will you see when it runs?

    four balls stopping one by one One moves sideways, one up and down, one diagonally, and one steeply. Each freezes gray on its third bounce. The last one stops about four and a half seconds in.

  2. Which ball stops first?

    the diagonal one The ball that starts at (300, 300). It isn’t the fastest. It runs into a floor and a wall, and every bounce counts, so it reaches three in about a second and a half. The ball moving only sideways is last.

Facilitator notes

Most people pick the fastest-looking ball for question 2. The real answer rewards reading the rule (“every wall hit counts”) rather than the motion, which is the habit this session builds.

The list is prepared for participants on purpose. ArrayList is new here, and today it only has to hold four objects. Anyone who missed Session 3 can start right here.

0:10 · 15 minutes · Short demo

Count it, then take the picture away

The facilitator runs ActiveTrace: ActiveBalls plus a few lines that count the active balls each frame and print a line whenever the count changes. Write your answers to questions 3–6 first. 

int lastActive = 4;

// at the end of draw():
  int active = 0;
  for (Ball b : balls) {
    if (b.bounces < 3) {
      active = active + 1;
    }
  }
  if (active != lastActive) {
    println("frame " + frameCount + ": " + active + " active");
    lastActive = active;
  }

  1. How many lines will the console print?

    four One each time a ball stops. If two balls stopped on the same frame, there would be fewer lines, because the count would drop by two at once.

  2. What are the first and last lines?

    frame 91: 3 active
frame 131: 2 active
frame 256: 1 active
frame 265: 0 active

    Frame 91 is the diagonal ball from question 2. Nobody is expected to predict the frame numbers. The order is the part to reason about.

  3. Break it: delete b.show();. What changes?

    the window goes blank, and the console doesn’t change The same four lines print on the same frames. The behavior never needed the picture. Separating that behavior from its drawing is what this session is about. The behavior on its own is called a model.

  4. Undo that. In move(), change bounces < 3 to bounces <= 3. What changes?

    same console, wrong picture The console prints the same four lines, because the counting loop still says < 3. But each gray ball keeps moving until it bounces once more. The rule “a ball is active” now lives in three places, and they disagree. In the build, one method, isActive(), puts it in one place.

What Processing hides

Processing lets a class reach for anything the sketch has: width, height, circle(). That is convenient, and it is why this Ball can’t run anywhere else. Here is the same class as a model only.

Model and view, mixed
class Ball {
  // fields and constructor

  void move() {
    if (bounces < 3) {
      // ... uses width and height
    }
  }

  void show() {
    if (bounces < 3) {
      fill(255);
    } else {
      fill(180);
    }
    circle(x, y, 40);
  }
}
Model only: Ball.java
public class Ball {
  // private fields and constructor

  public boolean isActive() {
    return bounces < 3;
  }

  public void move(int w, int h) {
    if (isActive()) {
      // ... uses w and h
    }
  }

  // getX(), getY(), getBounces()
}
  • A model is the state and the rules. A view is how they are drawn. The model on the right never draws, and it is told the size of its world instead of reading it from a window.
  • Once they are apart, the model can go anywhere: into plain Java, into a test, onto the AP exam. The view stays in the sketch.
Facilitator notes

Question 5 is the hinge of the session. Run it on screen and let the blank window sit there while the console keeps printing. It makes “the model doesn’t need the picture” obvious in a way no diagram does.

Question 6 is a real bug pattern: the same condition written in several places, edited in one. It motivates isActive() better than any rule about avoiding duplicate code.

0:25 · 25 minutes · Guided build

Pull the model out, with the picture on

Work in ActiveBalls. Every supported mission has to leave the picture exactly as it was, so the running sketch is your first test. The supported missions end at ModelViewCheckpoint. If you fall behind, open that and carry on from there.

Supported

Mission 1

Take the drawing out

Move show() out of Ball and into the sketch as void drawBall(Ball b), using b.x, b.y, and b.bounces. Change move() to move(int w, int h), use w and h where it said width and height, and call b.move(width, height); and drawBall(b);.

Expect  No visible change. Ball no longer uses anything that belongs to Processing.

Mission 2

Name the rule

Add boolean isActive() { return bounces < 3; } to Ball. Use isActive() in move() and in drawBall() in place of each bounces < 3.

Expect  No visible change. The rule now lives in one place, so question 6’s bug can’t happen anymore.

Mission 3

Ask the collection

In the sketch, write int countActive(): loop over balls, count the ones where isActive() is true, and return the count. Add textSize(16); to setup(), and show it with fill(0); text(countActive() + " active", 10, 25);

Expect  “4 active” in the corner, dropping by one as each ball stops, and reaching 0 about four and a half seconds in. This is ModelViewCheckpoint.

Independent extension

Extension 1

Clear the stopped balls

Write int removeInactive(): loop through balls backward, remove every ball that is not active, and return how many you removed. Call it when the c key is pressed, and print the result.

Expect  c makes the gray balls disappear, and the console reports how many went. An ArrayList can shrink. An array can’t.

Extension 2

Add by clicking

Add mousePressed(): add a new Ball at the mouse, kept inside the walls with constrain, with speeds from random(-6, 6).

Expect  Each click adds a white ball and raises the count by one. The input stays in the sketch. The model only receives a new ball. One answer to both extensions is ModelViewComplete.

Facilitator notes

“Refactor with the picture on” is the move to teach. A change that breaks the picture is caught in seconds, and students trust a change once the sketch still looks right.

Mission 3 is a complete free-response Question 3 answer in miniature: loop, condition, count, return. Point out that it calls isActive() instead of repeating bounces < 3. Calling the method you were given is how those questions work.

In extension 1, someone will remove inside a for (Ball b : balls) loop. Java stops that with a ConcurrentModificationException. Someone else will loop forward with an index and skip a ball. The tests in the transfer catch that one.

0:55 · 15 minutes · Java transfer

The model, with no window at all

Ball.java is the model from the right-hand side above, in full. BallModel.java holds the prepared collection. Before you open it, write countActive() yourself from this header. 

/** Returns how many balls are still active. */
public int countActive()
public int countActive() {
  int count = 0;
  for (Ball b : balls) {
    if (b.isActive()) {
      count++;
    }
  }
  return count;
}

Start the count at 0, visit every ball, test with the method you were given, return the count. A loop with an index, balls.get(i), earns the same credit.

import java.util.ArrayList;

public class BallModel {
  private ArrayList<Ball> balls;
  private int width;
  private int height;

  public BallModel(int w, int h) {
    balls = new ArrayList<Ball>();
    width = w;
    height = h;
  }

  /** Adds the four starting balls, the same ones the sketch starts with. */
  public void addStartingBalls() {
    balls.add(new Ball(60, 200, 4, 0));
    balls.add(new Ball(200, 60, 0, -3));
    balls.add(new Ball(300, 300, -5, 5));
    balls.add(new Ball(120, 330, 2, 6));
  }

  public void add(Ball b) {
    balls.add(b);
  }

  public int size() {
    return balls.size();
  }

  /** Moves every ball one frame. */
  public void step() {
    for (Ball b : balls) {
      b.move(width, height);
    }
  }

  /** Returns how many balls are still active. */
  public int countActive() {
    int count = 0;
    for (Ball b : balls) {
      if (b.isActive()) {
        count++;
      }
    }
    return count;
  }

  /** Removes every ball that is no longer active. Returns how many it removed. */
  public int removeInactive() {
    int removed = 0;
    for (int i = balls.size() - 1; i >= 0; i--) {
      if (!balls.get(i).isActive()) {
        balls.remove(i);
        removed++;
      }
    }
    return removed;
  }

  public static void main(String[] args) {
    BallModel model = new BallModel(400, 400);
    model.addStartingBalls();

    int frame = 0;
    int active = model.countActive();
    while (active > 0) {
      frame++;
      model.step();
      int now = model.countActive();
      if (now != active) {
        System.out.println("frame " + frame + ": " + now + " active");
        active = now;
      }
    }
  }
}

Test what the picture can’t

BallModelTest.java checks one case per line: the third-bounce boundary, a corner hit that counts twice, an empty model, all active, none active, and three stopped balls side by side. Predict PASS or FAIL for each line before you run java BallModelTest.

public class BallModelTest {

  public static void main(String[] args) {
    // isActive: the boundary at the third bounce
    Ball corner = new Ball(370, 370, 15, 15);
    corner.move(400, 400);
    check("a corner hit counts twice", 2, corner.getBounces());
    check("two bounces is still active", true, corner.isActive());

    Ball runner = new Ball(200, 200, 10, 0);
    for (int frame = 1; frame <= 100; frame++) {
      runner.move(400, 400);
    }
    check("after 100 frames, bounces", 3, runner.getBounces());
    check("after 100 frames, active", false, runner.isActive());

    // countActive: empty, all, some, none
    check("empty model, countActive", 0, new BallModel(400, 400).countActive());
    check("starting four, countActive", 4, stepped(0).countActive());
    check("after 91 frames, countActive", 3, stepped(91).countActive());
    check("after 265 frames, countActive", 0, stepped(265).countActive());

    // removeInactive: three stopped balls side by side
    BallModel late = stepped(260);
    check("after 260 frames, removeInactive", 3, late.removeInactive());
    check("after 260 frames, size after", 1, late.size());
  }

  /** Returns a model with the four starting balls, run for the given number of frames. */
  private static BallModel stepped(int frames) {
    BallModel model = new BallModel(400, 400);
    model.addStartingBalls();
    for (int frame = 1; frame <= frames; frame++) {
      model.step();
    }
    return model;
  }

  private static void check(String name, int expected, int actual) {
    report(name, expected == actual, "" + expected, "" + actual);
  }

  private static void check(String name, boolean expected, boolean actual) {
    report(name, expected == actual, "" + expected, "" + actual);
  }

  private static void report(String name, boolean passed, String expected, String actual) {
    String result = passed ? "PASS" : "FAIL";
    System.out.println(result + "  " + name + ": expected " + expected + ", got " + actual);
  }
}
PASS  a corner hit counts twice: expected 2, got 2
PASS  two bounces is still active: expected true, got true
PASS  after 100 frames, bounces: expected 3, got 3
PASS  after 100 frames, active: expected false, got false
PASS  empty model, countActive: expected 0, got 0
PASS  starting four, countActive: expected 4, got 4
PASS  after 91 frames, countActive: expected 3, got 3
PASS  after 265 frames, countActive: expected 0, got 0
PASS  after 260 frames, removeInactive: expected 3, got 3
PASS  after 260 frames, size after: expected 1, got 1

Everything passes, which only matters once you see what fails. Try the two questions below.

  1. A colleague writes isActive() as return bounces <= 3;. Which tests fail?

    FAIL  after 100 frames, active: expected false, got true
FAIL  after 91 frames, countActive: expected 3, got 4
FAIL  after 265 frames, countActive: expected 0, got 2
FAIL  after 260 frames, removeInactive: expected 3, got 2
FAIL  after 260 frames, size after: expected 1, got 2

    Five failures from one character. “After 100 frames, bounces” still passes, because the ball has bounced exactly three times by then. It just hasn’t stopped. A boundary test only helps when it sits right on the boundary.

  2. Another colleague writes removeInactive() with a forward loop, for (int i = 0; i < balls.size(); i++). Which tests fail? Does java BallModel still match the sketch?

    FAIL  after 260 frames, removeInactive: expected 3, got 2
FAIL  after 260 frames, size after: expected 1, got 2

    And yes, java BallModel still prints the same four lines, because main never removes anything. Removing index 1 slides the next ball into index 1, and the loop moves on to index 2 and skips it. Neither the sketch nor main could have shown you this bug. Only a test with stopped balls side by side can.

Facilitator notes

Before anyone reads the test file, ask the room to list the cases they would test. Then compare with the file. The list on FRQ (empty list, one element, nothing matches, everything matches) is the place to start, and “side by side” is the case for any method that removes.

Each test is one line: a name, an expected value, and the actual call. Students can write that before they know any testing framework, and the expected column is where the thinking happens. Port your own project applies the same process to a year of real student sketches.

What counts as evidence?

In groups of three or four. One person shares their screen. Everyone answers:

Discussion prompt. A student’s countActive() passes every test. What else would you want to see before you were sure they understand it? Which would you assess: the sketch, the tests they wrote, or a written explanation?

“Passing my tests only shows the method is right. I want to see the tests the student would have written. If they list the empty case and the side-by-side case without being told, they understand the traversal. I’d assess a short written explanation most heavily: ‘Why does removeInactive loop backward?’ A student who can answer that in two sentences has learned something that transfers to any language.”

AP-style multiple choice

Which call shows the error?

/** Precondition: top <= bottom */
public static int countBetween(ArrayList<Double> ys, double top, double bottom) {
  int count = 0;
  for (double y : ys) {
    if (y > top && y <= bottom) {
      count++;
    }
  }
  return count;
}

The method does not always work as intended. Which of the following calls returns a value different from the intended result?

  1. ys contains [50.0, 150.0, 250.0]; top is 100, bottom is 200
  2. ys contains [100.0, 300.0]; top is 100, bottom is 200
  3. ys is empty; top is 100, bottom is 200
  4. ys contains [200.0, 250.0]; top is 100, bottom is 200
  5. ys contains [150.0, 150.0, 150.0]; top is 100, bottom is 200

B 100 is between 100 and 200 inclusive, so the intended result is 1. The method uses y > top, skips 100, and returns 0. D tests the other boundary, which the method gets right: it returns 1, as intended. A, C, and E never put a value on a boundary, so a broken boundary can’t show up in them.
