The shortcut

Rebuild something you already made

You do not need a new project to learn AP Java. You need to take one you already finished and rewrite it without the canvas. Everything the exam asks you to write, you have already written — in a different costume. This page shows the costume change on real code from a year of student sketches.

Do this once, properly, early in the course. Two hours porting your own bouncing-ball sketch will teach you more about private, double, constructors and accessors than two weeks of reading about them, because you already know exactly what the program is supposed to do.

Step one

Your Ball class is a Question 2 answer

Free-response Question 2 is worth 7 points and asks you to design a class with a header, instance variables, a constructor, and a method. Here is a class from last year's collision sketch, next to the same class written the way a rubric wants it.

What you wrote
class Ball {
  float x;
  float y;
  float dx;
  float dy;
  float r;

  Ball() {
    x = random(100, 700);
    y = random(100, 700);
    dx = random(-5, 5);
    dy = random(-5, 5);
    r = 10;
  }

  void display() {
    fill(200);
    circle(x, y, r);
  }

  void move() {
    x = x + dx;
    y = y + dy;
  }
}
What earns the points
public class Ball {
  private double x;
  private double y;
  private double dx;
  private double dy;
  private double r;

  public Ball(double startX, double startY) {
    x = startX;
    y = startY;
    dx = 1.5;
    dy = 2.0;
    r = 10;
  }

  public double getX() { return x; }
  public double getY() { return y; }

  public void move() {
    x = x + dx;
    y = y + dy;
  }

  public String toString() {
    return "Ball at (" + x + ", " + y + ")";
  }
}

Six changes, and that is the whole exercise

  • class → public class, and the file must be named Ball.java.
  • Fields become private. Across a full year of student sketches, 140 files, there is not one access modifier. On a rubric this is points, every time.
  • float → double. Mechanical, but float is not in the tested subset at all.
  • The constructor takes parameters. Yours hard-coded random() inside. Exam constructors are handed their starting values.
  • Accessors appear. Once the fields are private, other classes need getX() to read them. In those same 140 sketches, only five methods returned a value — nearly everything was void.
  • display() → toString(). The object still describes itself; it just does it in words now.
Step two

Your collision loop is a Question 3 answer

This is the one worth sitting with. Question 3 gives you a collection of objects and asks you to count the ones matching some condition, usually by comparing items against each other. Look at what you already wrote to make balls bounce off one another:

Your collision check
for (int i = 0; i < ballList.length; i++) {
  for (int j = 0; j < ballList.length; j++) {
    if (i != j) {
      float d = dist(
        ballList[i].x, ballList[i].y,
        ballList[j].x, ballList[j].y);

      if (d < ballList[i].r) {
        bounce = bounce + 1;
      }
    }
  }
}
The same thing, exam-style
public int countOverlaps() {
  int count = 0;

  for (int i = 0; i < balls.size(); i++) {
    for (int j = i + 1; j < balls.size(); j++) {

      if (balls.get(i).overlaps(balls.get(j))) {
        count++;
      }
    }
  }

  return count;
}

Same algorithm. Three differences. The array became an ArrayList, so [i] became .get(i) and .length became .size(). The method returns a count instead of updating a global. And the inner loop starts at j = i + 1 rather than 0.

That last one is worth a minute. Starting at i + 1 visits each pair exactly once; starting at 0 with an i != j guard visits every pair twice, once in each direction. For counting, that doubles your answer. This is a classic all-pairs pattern and it shows up constantly.

For scale: the 2026 exam's Question 3 asked students to compare two lists of student records and count how many people appeared in both with a higher value in one than the other. Structurally, that is your bouncing balls.

Step three

Your grid game is a Question 4 answer

2D arrays are the biggest genuinely new thing in the course — those 140 sketches contain not a single [][] — and they are worth 6 points on the free response. But you have already thought in grids. In a typical grid project, moving a character looks like this:

Grid by pixel arithmetic
float characterX = 25;
float characterY = 25;

void keyPressed() {
  if (key == 'd') {
    characterX = characterX + 100;
  } else if (key == 'w') {
    characterY = characterY - 100;
  }
}

// the grid is implied by the +100
rect(characterX, characterY, 50, 50);
Grid as a real 2D array
private String[][] grid;
private int row;
private int col;

public void moveRight() {
  if (col < grid[0].length - 1) {
    col++;
  }
}

// the grid is the actual data
String here = grid[row][col];

You were already storing a grid — in pixels. characterX / 100 was your column number all along. A 2D array just stores that directly, so the grid can hold contents (a wall, a key, a score) instead of only a position.

The two facts to burn in: grid.length is the number of rows, grid[0].length is the number of columns, and the traversal is always for (row) { for (col) { grid[row][col] } }. Row first, every time.

Pick one

Four projects worth porting

Ranked by how much exam ground they cover per hour spent.

Best

The bouncing balls / collision sketch. Gets you a class with private fields and accessors (Q2), an array or ArrayList of objects, and an all-pairs nested traversal that returns a count (Q3). That is over half the free-response section in one port.

Then

The Rain Game. It already has three classes — Catcher, Drop, Timer — which is exactly the multi-class setup Question 3 hands you. Port Drop first, then write a method on the game class that counts how many drops were caught.

Then

Any grid project. Interactive Grid System, the escape-room game, snow accumulation. Replace the pixel arithmetic with a real 2D array and write one method that scans it — count the filled cells, find the largest value, check whether a row is complete.

Stretch

Give a project a save file. Write the final scores from your game to a text file, then read them back with Scanner and report the highest. File reading is new to the course as well as to you, so almost nobody has practised it — and doing it with your own data beats doing it with a worksheet.

One skill that transfers untouched

Your whole Unit 7 was debugging — handed a broken Rain Game and told to find the fault. That is the same skill as a large share of the multiple-choice section, where you are shown a method that almost works and asked which line is wrong, what it prints instead, or which input breaks it.

The only new part is that Java throws named exceptions rather than just misbehaving. Learn the four on the setup page and you are reading error messages, not guessing at them.
