0:00 · 10 minutes · Run

Get it moving

Open MovingBall/MovingBall.pde from the download, or paste this into a new sketch, and press Run.

float y = 0;

void setup() {
  size(400, 400);
}

void draw() {
  background(255);
  circle(200, y, 40);
  y = y + 2;
}

Expect  A white 400×400 window. A circle with a black outline starts half-hidden at the top center, slides straight down, and leaves the bottom in about three and a half seconds. Then the window stays empty.

Facilitator notes

Nothing else starts until every screen shows the ball. Anyone stuck goes to Your first sketch, and a co-facilitator follows them there.

Ask one question before moving on: “Nobody called draw(). So who did?” Don’t answer it yet. It comes back at 0:55.

0:10 · 20 minutes · Predict

Call each frame before it prints

FrameByFrame.pde is the same ball at one frame per second. It prints where it drew each frame and stops after five. Write your answers to questions 1–3 before you press Run. 

float y = 0;

void setup() {
  size(400, 400);
  frameRate(1);
}

void draw() {
  background(255);
  circle(200, y, 40);
  println("frame " + frameCount + ": drew at y = " + y);
  y = y + 2;
  if (frameCount == 5) {
    noLoop();
    println("after frame 5, y = " + y);
  }
}

  1. What does the console print for frame 1?

    frame 1: drew at y = 0.0 The circle is drawn before y changes. And 0.0, not 0, because y is a float.

  2. What does it print for frame 5?

    frame 5: drew at y = 8.0 Frame n draws at 2(n−1). Many people say 10. That is the next question.

  3. What is the last line?

    after frame 5, y = 10.0 The variable has already moved past the last position drawn. The update runs after the drawing, every frame.

  4. Back in MovingBall at full speed: on which frame is the circle’s center first drawn below the bottom edge, past y = 400?

    frame 202 It draws at y = 402.0. Frame 201 draws exactly on the edge at 400. At Processing’s default 60 frames per second, that is about 3.4 seconds, which matches what you saw.

  5. Move the line float y = 0; from the top of MovingBall to the first line inside draw(). What does the ball do now?

    it never moves Each call to draw() creates a new local y, sets it to 0, draws, adds 2, and throws it away when the method ends. State that has to outlast one frame has to live outside draw(). That is scope, and it becomes “instance variable” at 0:55.

Facilitator notes

Collect predictions for frame 5 before anyone runs it, by poll or in the chat. A split between 8 and 10 is the best possible outcome: it is the draw-then-update order, discovered rather than told.

frameRate(1) is the most useful thing in this session for students. Any animation can be slowed until it can be traced.

Question 5 is the scope lesson. Have people actually make the change and run it. Seeing a ball refuse to move sticks longer than the explanation.

0:30 · 25 minutes · Change

Four missions

Work in MovingBall. Before each run, say out loud what you expect. Each mission says what “working” looks like.

Mission 1

Faster

Change the 2 in y = y + 2; to 5.

Expect  The ball leaves the window in under a second and a half. In FrameByFrame, frame 5 would draw at 20.0.

Mission 2

Name the speed

Add float speed = 2; under float y = 0;, and change the update to y = y + speed;.

Expect  No visible change at all. That is the point: speed is now state too, so the program can change it while it runs.

Mission 3

Wrap around

After the update line, add if (y > height + 20) { y = -20; }

Expect  The ball leaves the bottom and slides back in from the top, forever. The 20s are the radius, so it is fully out of sight before it jumps.

Mission 4 · stretch

Bounce

Start at y = 20. Replace the wrap with: when the ball reaches the top or bottom edge, flip the sign of speed.

Expect  The ball bounces between the top and bottom edges forever. One answer is BouncingBall/BouncingBall.pde in the download.

Facilitator notes

Someone will try mission 4 starting from y = 0. The ball jitters at the top instead of bouncing, because y < 20 is true every frame and speed flips back and forth. Put that screen up and trace two frames together with frameRate(1). It is the best debugging moment of the session.

Mission 2 matters more than it looks: it is the step that turns a magic number into a field, and Session 3 builds on it.

0:55 · 10 minutes · Translate

What Processing hides

Back to the opening question: who calls draw()? Here is the same sketch written as the Java class Processing actually builds. It runs outside the editor with Processing’s library.

What you wrote
float y = 0;

void setup() {
  size(400, 400);
}

void draw() {
  background(255);
  circle(200, y, 40);
  y = y + 2;
}
What Processing runs
import processing.core.PApplet;

public class MovingBall extends PApplet {

  private float y = 0;

  public void settings() {
    size(400, 400);
  }

  public void draw() {
    background(255);
    circle(200, y, 40);
    y = y + 2;
  }

  public static void main(String[] args) {
    PApplet.main("MovingBall");
  }
}
  • The sketch is a class. The editor wraps your code in one, named after the sketch.
  • The global is a field. y outlives each frame because it belongs to the object, not to draw(). That is why question 5 froze the ball.
  • draw() is a method someone else calls. Processing’s own loop calls it about 60 times a second. You never do.
  • main was there all along. It starts the loop. Outside the editor, size() moves to settings().
Facilitator notes

Keep this short and conceptual. Nobody needs to run the right-hand version today. Compare has it, and nine more pairs, for later.

extends PApplet uses inheritance, which is no longer on the AP exam. Name it once (“Processing’s machinery comes in here”) and move on.

1:05 · 25 minutes · Port

Same state, no window

AP Java has no animation loop and no screen. So you write the loop yourself, and each frame becomes a line of text. The test: the output must match the FrameByFrame console line for line. 

public class MovingBall {

  public static void main(String[] args) {
    double y = 0;

    for (int frame = 1; frame <= 5; frame++) {
      System.out.println("frame " + frame + ": drew at y = " + y);
      y = y + 2;
    }
    System.out.println("after frame 5, y = " + y);
  }
}
frame 1: drew at y = 0.0
frame 2: drew at y = 2.0
frame 3: drew at y = 4.0
frame 4: drew at y = 6.0
frame 5: drew at y = 8.0
after frame 5, y = 10.0

Identical to the sketch. Name what changed: float became double, frameCount became a loop counter you control, println became System.out.println, and the picture became text.

Now trace a bounce before you run it

BounceTrace.java applies the mission 4 rule with no drawing. Start at 360 moving 15 per frame. Write all six lines on paper first.

public class BounceTrace {

  public static void main(String[] args) {
    double y = 360;
    double speed = 15;

    for (int frame = 1; frame <= 6; frame++) {
      y = y + speed;
      if (y > 380 || y < 20) {
        speed = -speed;
      }
      System.out.println("frame " + frame + ": y = " + y + ", speed = " + speed);
    }
  }
}
frame 1: y = 375.0, speed = 15.0
frame 2: y = 390.0, speed = -15.0
frame 3: y = 375.0, speed = -15.0
frame 4: y = 360.0, speed = -15.0
frame 5: y = 345.0, speed = -15.0
frame 6: y = 330.0, speed = -15.0

Frame 2 overshoots to 390 before turning around. In the sketch, that is the ball poking past the edge for one frame. Here it is just a number, and the trace shows it to you.

Facilitator notes

Have people paste their console output next to the FrameByFrame output in the chat. A mismatch is usually the loop starting at 0 instead of 1, which is a good conversation about where the frame counter came from.

The bounce trace is where the visual intuition pays off: people who watched the ball overshoot catch the 390. People who only read the code often don’t.

1:30 · 10 minutes · AP transfer

An exam-style question

No Run button. Commit to a letter.

Multiple choice

What is printed?

double y = 370;
double speed = 8;
for (int k = 0; k < 3; k++) {
  y = y + speed;
  if (y > 380 || y < 20) {
    speed = -speed;
  }
}
System.out.println(y + " " + speed);
  1. 386.0 8.0
  2. 378.0 -8.0
  3. 394.0 8.0
  4. 370.0 -8.0
  5. 378.0 8.0

B  378.0 -8.0 After pass 1, y is 378 and nothing flips. After pass 2, it is 386, past 380, so speed becomes −8. Pass 3 brings y back to 378 still moving up. E is the answer for anyone who forgets the flip persists. A is the answer for anyone who stops a pass early.

Facilitator notes

This is the same shape as the bounce trace, with new numbers and no frame labels. Point out that the distractors come from real mistakes, which is how good AP distractors work. Then invite participants to write one for their own students.

Stretch · if you are running 120 minutes · preview of Session 3

Put the state in an object

y and speed belong together. BallWorld.java moves them into a Ball class. It prints exactly what BounceTrace prints. 

public class BallWorld {

  public static void main(String[] args) {
    Ball b = new Ball(360, 15);
    for (int frame = 1; frame <= 6; frame++) {
      b.move();
      System.out.println("frame " + frame + ": y = " + b.getY() + ", speed = " + b.getSpeed());
    }
  }
}

class Ball {
  private double y;
  private double speed;

  public Ball(double startY, double startSpeed) {
    y = startY;
    speed = startSpeed;
  }

  /** One frame of motion: move, then turn around at an edge. */
  public void move() {
    y = y + speed;
    if (y > 380 || y < 20) {
      speed = -speed;
    }
  }

  public double getY() {
    return y;
  }

  public double getSpeed() {
    return speed;
  }
}

In a classroom, Ball would live in its own Ball.java. It is in one file here so it runs anywhere with one paste.
