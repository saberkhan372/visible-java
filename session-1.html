Session 01 · Sunday, November 8 · 7–9 a.m. PT / 10 a.m.–noon ET

Make state visible

One ball, moving down a window. You predict where it will be, change what it remembers, and then call draw() yourself in plain Java. By the end, “a variable holds state” and “a method is called repeatedly” are things you have watched happen.

Java ideas
Variables as state, assignment and expressions, scope, methods that something else calls, and calling a method yourself.
AP link
AP CS A Unit 1: variables, expressions, and tracing values through repeated execution. Outside AP: an intro programming, creative coding, or physics-of-motion lesson.
Files
session-1-files.zip: starter, prediction, checkpoint, and completed sketches; three Java files; an editable student handout and teacher guide.
You leave with
A starter sketch, a prediction sheet, its plain-Java counterpart, and a 30-minute classroom activity.

0:00 · 10 minutes · Predict and discuss

Call it before you run it

Read this sketch. Before anyone presses Run, answer the two questions. Then open MovingBall from the download and run it.

float y = 0;

void setup() {
  size(400, 400);
}

void draw() {
  background(255);
  circle(200, y, 40);
  y = y + 2;
}

  1. What will you see when it runs?

    a ball sliding down A white 400×400 window. A circle with a black outline starts half-hidden at the top center, slides straight down, and leaves the bottom in about three and a half seconds.

  2. Nothing in the sketch calls draw(). So who does?

    Processing does About 60 times a second. You will call it yourself in plain Java at 0:55.

Facilitator notes

Collect answers to question 1 in the chat before running. “It draws a circle” is the common answer; the motion is the surprise, so let it be one.

Anyone whose sketch doesn’t run goes to Your first sketch with a co-facilitator. Everyone else moves on, so setup problems don’t hold the room.

0:10 · 15 minutes · Short demo

Slow it down, break it, open it up

The facilitator runs FrameByFrame: the same ball at one frame per second, printing where it drew each frame. Write your answers to questions 3–5 first. The if at the end only stops it after five frames. Decisions are Session 2. 

float y = 0;

void setup() {
  size(400, 400);
  frameRate(1);
}

void draw() {
  background(255);
  circle(200, y, 40);
  println("frame " + frameCount + ": drew at y = " + y);
  y = y + 2;
  if (frameCount == 5) {
    noLoop();
    println("after frame 5, y = " + y);
  }
}

  1. What does the console print for frame 1?

    frame 1: drew at y = 0.0 The circle is drawn before y changes. 0.0, not 0, because y is a float.

  2. What does it print for frame 5?

    frame 5: drew at y = 8.0 Frame n draws at 2(n−1). Many people say 10, which is the next answer.

  3. What is the last line?

    after frame 5, y = 10.0 The variable has already moved past the last position drawn. The update runs after the drawing, every frame.

  4. Break it: move float y = 0; in MovingBall to the first line inside draw(). What happens?

    it never moves Each call to draw() creates a new local y, sets it to 0, draws, adds 2, and throws it away. State that has to outlast one frame has to live outside draw(). That is scope.

What Processing hides

Here is the class Processing actually builds from the sketch. You won’t run it today. It explains the last answer.

What you wrote
float y = 0;

void setup() {
  size(400, 400);
}

void draw() {
  background(255);
  circle(200, y, 40);
  y = y + 2;
}
What Processing runs
public class MovingBall extends PApplet {

  private float y = 0;

  public void settings() {
    size(400, 400);
  }

  public void draw() {
    background(255);
    circle(200, y, 40);
    y = y + 2;
  }

  public static void main(String[] args) {
    PApplet.main("MovingBall");
  }
}
  • The sketch is a class, and the global y is a field. It belongs to the object, so it outlives each frame.
  • draw() is a method that someone else calls, Processing’s own loop. main starts that loop.
Facilitator notes

Take a poll on frame 5 before running. A split between 8 and 10 is the best possible outcome: the draw-then-update order gets discovered rather than told.

frameRate(1) is the most useful tool in this session for students: any animation can be slowed until it can be traced.

extends PApplet uses inheritance, which is no longer on the AP exam. Name it once (“Processing’s machinery comes in here”) and move on.

0:25 · 25 minutes · Guided build

Change what it remembers

Work in MovingBall. Before each run, say what you expect. The supported missions end at MovingBallCheckpoint. If you fall behind, open that and carry on from there.

Supported

Mission 1

Faster

Change the 2 in y = y + 2; to 5.

Expect  It leaves the window in under a second and a half. In FrameByFrame, frame 5 would draw at 20.0.

Mission 2

Name the speed

Add float ySpeed = 2; and change the update to y = y + ySpeed;.

Expect  No visible change. That is the point: speed is state now, so the program could change it.

Mission 3

A second direction

Add float x = 0; and float xSpeed = 1.5;. Draw with circle(x, y, 40); and add x = x + xSpeed;.

Expect  It moves diagonally down and to the right and leaves through the bottom about three-quarters of the way across. This is MovingBallCheckpoint.

Independent extension

Extension 1

See every frame

Delete background(255); from draw(), and add it to setup() instead.

Expect  A trail. Every frame stays on screen, so the whole history of the state is visible at once.

Extension 2

Let speed change too

Start ySpeed at 0 and add ySpeed = ySpeed + 0.2; at the end of draw().

Expect  It starts slowly and speeds up, and with the trail on, the path curves like a thrown ball. One answer is FallingBall.

Facilitator notes

Mission 2 matters more than it looks: it turns a magic number into a variable, and Session 3 turns that variable into a field.

Experienced Java teachers will finish fast. Point them to the extensions and to the studio question rather than to helping neighbors: they came to learn too.

No conditionals in this session on purpose. Someone will want the ball to bounce. Tell them that is exactly where Session 2 starts.

0:55 · 15 minutes · Java transfer

Same state, no window

AP Java has no animation loop and no screen. So you write the loop, and each frame becomes a line of text. The test: the output must match the FrameByFrame console line for line. Run each file with any method from Running plain Java. 

public class MovingBall {

  public static void main(String[] args) {
    double y = 0;

    for (int frame = 1; frame <= 5; frame++) {
      System.out.println("frame " + frame + ": drew at y = " + y);
      y = y + 2;
    }
    System.out.println("after frame 5, y = " + y);
  }
}
frame 1: drew at y = 0.0
frame 2: drew at y = 2.0
frame 3: drew at y = 4.0
frame 4: drew at y = 6.0
frame 5: drew at y = 8.0
after frame 5, y = 10.0

Identical. float became double, frameCount became a loop counter you control, and the picture became text.

Now you call draw()

Back to question 2. In plain Java, nothing calls draw() for you, so main calls it by name, five times. Same output again, without even a loop.

public class ExplicitDraw {

  static double y = 0;

  static void draw() {
    System.out.println("drew at y = " + y);
    y = y + 2;
  }

  public static void main(String[] args) {
    draw();
    draw();
    draw();
    draw();
    draw();
    System.out.println("after five calls, y = " + y);
  }
}

static here means one y, owned by the class. That is AP topic 3.7, and Session 3 replaces it with an object.

Trace before you run

FallingTrace.java is the Extension 2 rule with whole numbers and no drawing. Write all five lines first.

public class FallingTrace {

  public static void main(String[] args) {
    int y = 0;
    int ySpeed = 0;
    int gravity = 2;

    for (int frame = 1; frame <= 5; frame++) {
      y = y + ySpeed;
      ySpeed = ySpeed + gravity;
      System.out.println("frame " + frame + ": y = " + y + ", ySpeed = " + ySpeed);
    }
  }
}
frame 1: y = 0, ySpeed = 2
frame 2: y = 2, ySpeed = 4
frame 3: y = 6, ySpeed = 6
frame 4: y = 12, ySpeed = 8
frame 5: y = 20, ySpeed = 10

Frame 1 doesn’t move at all, because y changes before ySpeed does. Swap the two update lines and every value changes. That’s the same draw-then-update order as question 4, in a new costume.

Facilitator notes

Have people paste their output next to the FrameByFrame output. A mismatch is usually a loop starting at 0, which is a good conversation about where the frame counter came from.

The point of ExplicitDraw is the answer to question 2, not static. Don’t let it become a lesson on static.

1:10 · 15 minutes · Colleague exchange

Where does this go in your teaching?

In groups of three or four. One person shares their screen. Everyone answers:

Discussion prompt. Where in your course would a moving ball fit, and what would you ask students to predict first? When students do this activity, what would you assess: the sketch, the prediction table, or the explanation?

“I’d use it in the second week of my intro course, the day we start variables. I’d ask the frame-5 question first, because I want the 8-versus-10 argument before anyone runs it. I would grade the prediction table and question 3 of the Explain section, not the sketch. A beautiful sketch can hide a student who doesn’t know why it moves.”

Facilitator notes

Mix AP and non-AP teachers in each group. The non-AP answers are often the most inventive placements, and the AP answers bring the tracing rigor.

Ask each group to put one sentence in the chat. Those sentences start Session 5’s studio.

1:30 · 30 minutes · Optional studio

Studio

Stay for whichever helps: one-on-one troubleshooting, the extensions, this AP-style question, or the classroom adaptation task.

AP-style multiple choice

What is printed?

int y = 0;
int speed = 3;
for (int k = 0; k < 4; k++) {
  y = y + speed;
  speed = speed - 1;
}
System.out.println(y + " " + speed);
  1. 12 3
  2. 6 -1
  3. 6 0
  4. 2 -1
  5. 5 1

B  6 -1 y goes 3, 5, 6, 6 while speed goes 2, 1, 0, −1. Each distractor is a real mistake. A forgets that speed changes. C stops a pass early, and E stops two passes early. D runs the two updates in the wrong order.
