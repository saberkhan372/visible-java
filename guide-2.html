7:00 to 7:30

Part 1: Welcome and shared work

The goal is that everyone sees two pieces of work from the group and one idea worth borrowing.

  1. Welcome, 5 minutes. Remind people that the session is recorded. New people give their name and what they teach. Everyone else skips introductions.
  2. Recap, 5 minutes. Saber opens the assignment and names what Session 1 covered: setup() and draw(), the pumpkin puzzle, and stamping with methods that take arguments. Point new people to the recap.
  3. Shared work, 15 minutes. Joshua picks the pieces ahead of time and asks before the session whether each person is happy to show theirs. Two are enough. Then ask for volunteers.
  4. Logistics, 5 minutes. Where the recording and assignment live, and how breakout rooms will work today.

The idea to draw out: where is (0, 0)?

Two submissions added a method of their own. In one, the shape stamps exactly at the mouse. In the other, it stamps down and to the right of it, and the author asked why. Show both, in that order.

// lands away from the mouse
translate(x, y);
ellipse(200, 100, 75, 75);
ellipse(200, 175, 100, 100);
ellipse(200, 275, 150, 150);

// lands on the mouse
translate(x, y);
ellipse(0, -90, 75, 75);
ellipse(0, -15, 100, 100);
ellipse(0, 85, 150, 150);

After translate(x, y), the point (0, 0) is the mouse. The first version was designed on a canvas with its middle near (200, 190), so every stamp is offset by that much. The second is drawn around (0, 0). Ask the group before explaining: what would you change? Subtracting 200 from each x and about 190 from each y fixes it.

This is worth the time because it is a question about arguments and reference points, which is Unit 1, and the picture shows the bug. It also sets up today: the same sketch gets a variable for position.

Keep this focused. If nobody volunteers after the two planned pieces, move on. If the room is lively it can run to 7:45, and Part 2 shrinks to 15 minutes.

7:30 to 7:50

Part 2: Session 2 and where it sits

Saber leads. The one idea: a program makes decisions by looking at its own state.

  1. From stamps to motion, 5 minutes. In the stamp scene draw() was empty, so stamps stayed. Put background and one stamp inside draw(), and give its x a variable. Now the scene from the assignment moves. Everyone keeps building on this one project for the rest of the series.
  2. Connecting the ideas, 5 minutes. People already wrote if (key == 'p') last week because they wanted something to happen. Today names what that was. State is a variable that lasts between frames. A condition is a question about state. An if is what the answer changes.
  3. The course around it, 5 minutes. Session 1 was Unit 1: variables, methods, arguments, integer division. Today is the first half of Unit 2: Boolean expressions and if. Loops are the other half of Unit 2, and they come in a later session. Show Unit 2 for the lesson list.
  4. Hand off, 2 minutes. Name the four steps people are about to do: predict, run, investigate, modify. If time is short, skip the name and let them do it.

Sessions 1 and 2 hold a lot. Say plainly that nobody needs all of it. One moving shape and one if is a complete result for today.

7:50 to 8:30

Part 3: Motion and conditionals

Joshua Hans leads, with at least 30 minutes and ideally 40. Two short examples to read together, then one to change in breakout rooms. The sketches below are a starting point, and Joshua’s versions replace them.

Example 1: two shapes, two speeds (about 8 minutes)

float carX = 0;
float busX = 0;

void setup() {
  size(600, 400);
}

void draw() {
  background(230);

  fill(40, 90, 200);
  rect(carX, 120, 60, 30);
  carX = carX + 3;

  fill(240, 180, 0);
  rect(busX, 240, 100, 40);
  busX = busX + 1;

  if (carX > width) {
    carX = 0;
  }
}
  • Predict. In chat, before running: what happens to the car when it reaches the right edge? What happens to the bus?
  • Run. The car comes back. The bus leaves and does not return. Nothing asks about busX.
  • Investigate. How often is the if checked? How often is it true? Why does the car slide fully off before it returns?
  • Modify. Bring the bus back too. Then make the car return as soon as its front touches the edge.

Example 2: a light the car obeys (about 10 minutes)

Now one object’s state decides what another does. The light is a boolean, and the space bar flips it.

float carX = 0;
boolean lightIsGreen = true;

void setup() {
  size(600, 400);
}

void draw() {
  background(230);

  if (lightIsGreen) {
    fill(0, 190, 80);
  } else {
    fill(220, 40, 40);
  }
  circle(450, 80, 50);

  if (lightIsGreen) {
    carX = carX + 3;
  }
  if (carX > width) {
    carX = 0;
  }

  fill(40, 90, 200);
  rect(carX, 220, 60, 30);
}

void keyPressed() {
  if (key == ' ') {
    lightIsGreen = !lightIsGreen;
  }
}
  • Predict. What does the car do on a red light? Where does it stop?
  • Run. It stops wherever it is, even after it has passed the light. Click inside the sketch first, so it hears the key.
  • Investigate. Which variable does the car read? Does the car know where the light is? What does ! do to lightIsGreen?
  • Modify. This is the breakout task below.

Breakout rooms: stop at the light (about 15 minutes)

Rooms of two or three. Everyone starts from Example 2 and takes whichever step fits.

  1. Stop only before the light. The car should run a red light it has already passed. Change the condition to if (lightIsGreen || carX > 450).
  2. Stop only when close. Write a distance method instead of using Processing’s dist, then stop the car when the light is red and the car is within 150 of it.
  3. Add a yellow. A boolean has two values and a stoplight has three. Change the light to an int or a String, and slow the car on yellow.
float distance(float x1, float y1, float x2, float y2) {
  float dx = x2 - x1;
  float dy = y2 - y1;
  return (float) Math.sqrt(dx * dx + dy * dy);
}

Math.sqrt is on the AP Java Quick Reference and returns a double, so the cast from Session 1 comes back. The same method is the start of collision detection: two circles touch when the distance between their centers is less than the sum of their radii.

If the room is quiet: keep live coding to 10 to 20 minutes and go to breakout rooms early. People talked more in small groups last time.

Second facilitator: visit rooms, note the questions, and bring one back to the whole group at 8:25.

Loops: saved for a later session. If someone asks for many cars, say that is exactly what a loop is for, and show one only if there is time.

Part 4: Guest and close

Alfred Thompson joins for the last half hour.

  • Conversation, 20 minutes. What has he seen work for a first lesson on conditionals? How does he choose projects that students want to keep extending? What would he tell a teacher starting AP CS A this year?
  • Questions, 5 minutes. Offer the chat as well as open mic.
  • Close, 5 minutes. Give the assignment below, and say when Session 3 is.
Before Session 3

Assignment: keep the same project

People continue the stamp scene from Session 1. Do as much as there is time for.

  1. Make one thing move. Give one stamp a variable for its position, and change it in draw().
  2. Add one decision. For example: no trees above a certain height, a shape that turns around at the edge, or a key that changes what gets stamped.
  3. Stretch. Use the distance method, so something happens when two shapes get close.

Post a screenshot or code in Google Classroom for feedback. Completed assignments are how we judge whether the pace is right, so there is no feedback form.

In the moment

Common questions

If you hearTry
“My shape lands in the wrong place.”Ask where (0, 0) is after translate. Draw the shape around it.
“My stamps disappear now.”background in draw() repaints every frame. Motion needs that, and stamping does not.
“The key does nothing.”Click inside the sketch first. It only hears keys when it has focus.
“The car never stops.”Ask what value would make the condition true, then print the variable.
“Why == and not =?”= stores a value. == asks a question and gives back true or false.
“Why not just use dist?”It works. Writing it once shows what it does, and Math.sqrt is the version on the exam.
“Is this on the exam?”Boolean expressions, if and else, and the Math class are Units 1 and 2.
